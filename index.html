How it works

Three steps from project to checkpoint.

A short setup, a clear handoff, and a review you can reverse.

  1. 01

    Point it at your project

    Use the guided /setup form or describe the project in chat. fluid-coding scans the folder and proposes a local project — nothing is written before you click Apply.

  2. 02

    Pick a task, hand off the brief

    Choose a task on the board, attach its Change Brief and let your existing agent — opencode or Claude Code — propose the changes. The brief gives it the context you already have.

  3. 03

    Review, apply, checkpoint

    Inspect the proposed patch, apply only what you trust, and restore the previous files from the checkpoint if it is not right. Your editor and your workflow stay in place.

Control by design

Your machine, your rules, your final say.

This is a local prerelease, scoped to the project you configure. There is no hosted index and no whole-organisation semantic search to sign up for.

  • Local-first. The app binds to 127.0.0.1 only; project files and checkpoints stay on your machine.
  • Propose by default. Agents suggest changes. Nothing is applied until you choose to apply it.
  • Every apply is checkpointed. Previous file contents are saved before a patch lands, so undo is exact.
  • Facts before narrative. LLM text is labelled enrichment and never used as evidence for a review decision.

FAQ

Good questions, straight answers.

Is this a prerelease?

Yes. This is v0.1.0-alpha.2, an early macOS build for people who want to try the review loop. Expect rough edges and please treat it as a preview, not a production toolchain.

What platforms are supported?

This build is for macOS on Apple silicon (arm64) only. There is no Intel Mac, Windows or Linux archive yet.

Why does macOS warn me when I open it?

The prerelease is ad-hoc signed and not notarized. Move fluid-coding.app to /Applications, run xattr -cr /Applications/fluid-coding.app, then open it. On first launch you may still need to right-click → Open.

Which agents can I use?

opencode and Claude Code are the adapters shown in this build. fluid-coding plugs into the agent you already run; it does not replace it. Forge adapters are not wired up in this prerelease.

Which languages does it understand?

TypeScript, JavaScript, Java and Pharo Tonel ship as language plugins. Analysis is scoped to the project you configure locally — there is no hosted multi-repo index.

Does my code leave the machine?

fluid-coding itself binds to 127.0.0.1 only and keeps project analysis and checkpoints local. If you enable an LLM narrative or use your own agent, that tool’s own provider and settings apply.
