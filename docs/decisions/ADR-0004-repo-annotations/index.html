ADR-0004 — Tags and views are files in .fluid/

  • Status: accepted
  • Date: 2026-11-24

Context

Architecture annotations are valuable only if they survive tool changes, reviews and agents. A database is fast but opaque, hard to review and easy to lose. Tags also need to be edited by humans, agents and rules, and diffed in pull requests.

Decision

Store taxonomy, tags, views, checks and config as plain JSON/TOML under .fluid/. The server loads and watches the folder; SQLite and in-memory indexes are disposable caches in .fluid-coding/cache/. Tags target provider-stable keys. Orphans are computed, not a stored status.

Consequences

  • Tag changes are reviewable in git and portable across machines.
  • Write paths must be atomic (temp file + rename) and validated with zod/serde.
  • A rename can orphan a tag; the UI must surface it and offer migration.
