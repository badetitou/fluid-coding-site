ADR-0027 — Local GenAI trace model from OTLP spans

  • Status: accepted
  • Date: 2026-11-26

Context

Durable dock sessions under .fluid-coding/sessions/ record successful runs, but not tool calls, timings or subagents. A user can reopen a conversation and still cannot answer “what did the agent do, in which order, and where did the time go?”. Provider CLIs can already export OpenTelemetry GenAI semantic-convention spans, so the missing piece is a local receiver and a normalized model, not a new instrumentation of every adapter by hand.

Reading the native databases of opencode or Claude Code would couple the workbench to private, unstable schemas and to a second tool loop. The workbench only needs a stable local wire contract.

Decision

  • The Rust server exposes a loopback-only OTLP/HTTP JSON receiver at POST /_telemetry/v1/traces. It accepts ExportTraceServiceRequest, caps the body at 2 MiB, caps raw attributes at 64 keys and 256 characters per value, and never forwards telemetry externally. CLI adapters inject the endpoint into the spawned provider process through OTLP environment variables.
  • Pin a subset of the GenAI semantic conventions: invoke_agent, chat, execute_tool, transfer, plan and exception, with provider-specific operation values preserved verbatim. Adapters normalize provider variants into one TraceSpan/TraceSession/SessionTrace model; raw attributes are kept capped and sorted for deterministic output.
  • fluid-core owns the trace types and the pure, deterministic build_session_graph. It performs no I/O, reads no clock and awaits nothing; the server supplies ingestion and storage.
  • Spans are appended atomically to .fluid-coding/traces/<safeConversationId>.jsonl, which is gitignored. Trace files are telemetry, not repository source of truth.
  • Correlation uses traceparent first, then conversation/session id plus time window when the trace context is missing. Unknown session ids yield empty sessions, not a 500.
  • Content capture is opt-in and off by default. Metadata only is stored by default; prompts, tool args and results are represented by a contentRef when enabled.
  • No native opencode or Claude Code database reads in v1.

Consequences

  • GenAI semconv is Development status, so the pinned subset can change. Variation is absorbed in adapters, never in routes or in the React client.
  • Traces stay local and gitignored; no external collector is contacted. Opt-in content capture keeps the default run private.
  • The shared fixture is parsed by Rust tests and by the contracts package, so a drift in the pinned subset is caught on both sides.
  • Future OTLP export or retroactive import of older traces is an additive adapter behind the same model; it does not require a new agent tool loop.
  • The normalizations and the graph builder need tests; the performance gates for a 10k-span graph are recorded in the budget doc and are not measured yet.
