ADR-0005 — MCP first, AgentPort for in-app agents

  • Status: accepted
  • Date: 2026-11-24

Context

Developers already use Claude Code, opencode, Codex and specialised agents such as the Pharo MCP stack. fluid-coding should not replace them or build another proprietary tool loop. It still needs an in-app chat that can see the current map, tags and change.

Decision

Expose fluid-coding’s capabilities as an MCP server first: get_matrix, cell_symbols, get_entity, get_relations, get_impact, get_diff, list_tags, propose_tag. External agents use these tools. The in-app agent uses the same tools through an AgentPort with adapters for opencode and Claude Code. Write tools require a trust mode and are audited.

Consequences

  • One tool contract, one documentation source, two integration surfaces.
  • The in-app agent must not get a private shortcut that external agents lack.
  • MCP schemas are part of the release contract and are tested with fixtures.
