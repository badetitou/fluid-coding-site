ADR-0049 — Pairing another device on the local network

  • Status: accepted
  • Date: 2026-11-27
  • Deciders: Benoit

Context

The server is loopback-only on purpose (ADR-0030): the API edits the repository and runs agent processes, and has no authentication. The user wants to continue a session from a phone on the same Wi-Fi: a “Pair other device” button in the status bar shows a QR code that opens the mobile web UI over a secure URL on the computer’s LAN address.

Opening the existing listener to the network would hand the whole API to anyone on the Wi-Fi.

Decision

  1. A second, opt-in listener. Nothing listens on the network until the user clicks the button. POST /api/pair/start (loopback listener only) binds the computer’s private LAN address (never 0.0.0.0) on a free port, serves the same web assets and API, and POST /api/pair/stop (or quitting the app) closes it and revokes every device. The loopback listener and ADR-0030 are unchanged.
  2. HTTPS with an in-memory self-signed certificate (rcgen, rustls), issued for the LAN IP at start. The phone shows a certificate warning once; the dialog shows the SHA-256 fingerprint so it can be compared. No certificate or key is written to disk.
  3. One-time token, then a device session. The QR encodes https://<ip>:<port>/pair#<token>; the token is 256 bits from the OS RNG, valid 5 minutes, single use, kept in the URL fragment so it is never sent to a server, logged or put in a Referer. The pair page posts it to POST /api/pair/redeem, which answers with a random 256-bit session in an __Host- prefixed HttpOnly; Secure; SameSite=Strict cookie. The unauthenticated redeem body is capped at 512 bytes. Comparisons are constant time.
  4. Everything on the network listener except static assets and redeem requires that cookie. The pairing management routes (start, stop, status, revoke) are mounted on the loopback router only, so a paired phone cannot pair further devices or stop the listener.
  5. Host and Origin policy on the network listener is the ADR-0030 policy built for <ip>:<port>; the loopback names are refused there, which closes DNS rebinding.
  6. The LAN address comes from the OS routing table (a UDP socket “connected” to a public address, which sends nothing). No address means a typed error and no listener.

Consequences

  • A paired device is fully trusted: it can run agents and edit the repository like the desktop UI. Pairing is therefore an explicit, visible, revocable act on the computer’s screen.
  • Sessions live in memory: restarting the app, or stopping pairing, signs every phone out.
  • Anyone on the Wi-Fi who can see the QR code within 5 minutes can pair; the dialog says so and the token dies on first use.
  • The self-signed certificate changes on every start, so the phone warns again after a restart. Persisting a certificate is a follow-up.
  • Browsers do not scope cookies by port: any other service on the computer’s LAN address receives the device cookie. The __Host- prefix and the 24-hour lifetime limit this; they do not remove it.

Alternatives considered

  • Bind the existing listener to 0.0.0.0. Rejected: exposes an unauthenticated API.
  • A tunnel (ngrok, Tailscale funnel). Rejected: not local, adds a third party.
  • Plain HTTP on the LAN. Rejected: the cookie and the agent output would travel in clear text, and mobile browsers restrict several APIs to secure contexts.
  • Token in a query string. Rejected: ends up in logs and history; the fragment does not.
