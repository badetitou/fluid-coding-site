ADR-0032 — Local task statuses and file persistence

  • Status: proposed
  • Date: 2026-11-26
  • Deciders: Benoit (to validate)
  • Amends: ADR-0011 (status set, local writes)

Context

ADR-0011 fixed four statuses (todo | in_progress | in_review | done) mirroring board.py and left local writes in memory. Dogfooding shows three defects:

  • .claude/issues/1-demo-videos.md has status: parked. TaskStatus::parse (crates/fluid-core/src/tasks/model.rs) accepts only todo, in-progress|inprogress|in progress, in-review|inreview|in review and done|closed; parse_local_markdown returns TaskError::UnknownStatus, fluid-index/src/tasks.rs drops the file with a warning, so GET /api/tasks returns [] and the warning surfaces only in /api/health.
  • create_task and patch_task (crates/fluid-server/src/routes/tasks.rs) only upsert into the in-memory store: POST /api/tasks returned local:1 and wrote no file. The number comes from TaskStore::next_local_number (max of the loaded tasks + 1), so local:1 collides with the dropped parked file.
  • Writing uses serialize_local_markdown, which emits only the board field set: unknown frontmatter keys of a hand-written issue would be lost on the first save.

The external convention is badetitou-team local-flow/scripts/board.py (0.6.1): STATUSES = ["todo", "in-progress", "in-review", "done"], move rejects any other status, issues with another status are listed on stderr as unknown status, new ids are max(ids) + 1, and new creates the directory with mkdir(parents=True, exist_ok=True). parked is therefore already outside that convention: it was written by hand.

Decision

  1. Canonical statuses are todo | in-progress | in-review | blocked | done in frontmatter and todo | in_progress | in_review | blocked | done on the wire. blocked ranks between in_review and done for sorting; nextStatus on the board skips it (blocking is an explicit move).
  2. Read aliases (case-insensitive, _ and spaces folded to -): inprogress, in progress → in-progress; inreview, in review, review → in-review; closed → done; parked, on-hold, waiting → blocked.
  3. Write canonical only. fluid-coding never writes an alias. A file keeps its original status token until its status is changed through fluid: an edit of title, body or labels rewrites the other fields and leaves status: parked as it is. The original token is carried in memory next to the task (not on the wire). Unknown frontmatter keys are preserved in their original order. Zero data loss is the invariant: load → save without a status change is byte-stable for the status line.
  4. Unknown status keeps the task visible. A task with an unrecognised status loads as todo with a parse warning naming the file and the token; its token is preserved as in rule 3. Dropping the task (today’s behaviour) is rejected because it hides work and causes number collisions.
  5. Numbering = max(number of every local issue file under every repo's .claude/issues/, including files that failed to parse but have an -filename prefix or anid:) + 1, computed from disk at creation time under the store’s write lock. The in-memory counter is never the source. File name: <n>-<slug>.md, slug from the title as in board.py.
  6. Atomic write. Serialize, write to .claude/issues/.<n>-<slug>.md.tmp in the same directory, fsync, then rename over the target. A failed write returns a typed ApiError and leaves the in-memory store unchanged (the store is updated after the rename succeeds).
  7. Directory policy. .claude/issues/ is created (create_dir_all) on the first local task creation, in the active project’s primary repo (first repo by key, as the loader orders them). Loading never creates it; a missing directory is not a warning.
  8. The store is a cache. The in-memory TaskStore is reloaded from disk on start and refreshed after each local write; disk wins on conflict.
  9. Forge tasks stay read-only for status and fields, as patch_task already enforces (connected forge issues are read-only). blocked is not mapped to any forge label in this ADR; GitHub/GitLab snapshots never produce it.
  10. Parse warnings reach the tasks API. Additive route GET /api/tasks/warnings returns [{ path, message }] (Rust struct, generated TS, fixture). GET /api/tasks keeps returning Task[] so no client breaks. The board shows a warning strip when the list is non-empty. /api/health keeps its copy.

What may ship before acceptance

Not a boundary change (implementable now, W2 tasks 1–5): file persistence for create/patch, disk-based numbering, atomic write, directory creation, store-as-cache, preservation of unknown keys and of the original status token, typed write errors, GET /api/tasks/warnings, and rule 4 with the current four statuses (an unknown token such as parked loads as todo with a warning).

Waits for acceptance (W2 task 6): adding blocked to TaskStatus, the alias table, zod taskStatusSchema, fixtures/contracts/tasks.json, the board column, and the migration below.

Implied changes (after acceptance)

  • fluid-core: TaskStatus::Blocked (label “Blocked”, frontmatter “blocked”, gitlab_label None), aliases, round-trip tests for every alias and for token preservation.
  • packages/contracts/src/tasks.ts: taskStatusSchema gains blocked; taskStatusLabels too.
  • fixtures/contracts/tasks.json: one task with "status": "blocked", tested in Rust and Vitest.
  • apps/web/src/lib/tasks.ts: taskStatuses and groupByStatus gain a Blocked column; the mock data and styles.css status colour follow.
  • badetitou-team board.py: add blocked to STATUSES (out-of-repo; until then board.py lists a blocked issue as unknown status but does not lose it).

Migration

1-demo-videos.md: rewrite status: parked to status: blocked explicitly in the same PR as the vocabulary change, with a note in the issue’s Result section. Its acceptance criteria are all checked and STATUS.md calls it done; the user parked it deliberately. If the user prefers, done is the other valid migration; that choice is part of validating this ADR. No other local issue exists.

Consequences

Positive:

  • The board shows every local issue; collisions with hidden files disappear.
  • Created and moved tasks survive a restart and are plain committed files, as ADR-0006 requires.
  • Hand-written issues and future board.py fields are not erased by fluid.

Negative:

  • A fifth status diverges from board.py until that script is updated.
  • Token preservation adds a small amount of state beside Task that is not on the wire.
  • Two concurrent writers (fluid and board.py) can still race on the number; the window is one creation and the loser gets a duplicate-key warning, not data loss.

Alternatives considered

  • Keep parked as its own status. Rejected by default: a sixth column for one file, and “parked” and “blocked” both mean “not moving, not done”. Valid if the user wants to distinguish a deliberate deferral from an external blocker.
  • Map parked to todo or done. Rejected as an alias: it changes meaning silently. done is acceptable only as an explicit one-file migration.
  • Rewrite aliases to canonical on any save. Rejected: it edits a field the user did not touch and breaks the zero-loss invariant.
  • Drop unknown statuses (current behaviour). Rejected: hides work and corrupts numbering.
  • Envelope { tasks, warnings } on GET /api/tasks. Rejected for now: breaking contract change for every client; the additive route gives the same information.
  • In-memory counter or a .fluid-coding/ sequence file. Rejected: the files are the truth; a separate counter drifts when issues are added by hand or by board.py.
