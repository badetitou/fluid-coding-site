ADR-0006 — Local single executable first; desktop and hosted later

  • Status: accepted
  • Date: 2026-11-24

Context

The product must work on a real repository, with git, file watching and agent processes. A cloud-only service cannot access those without a sync layer. A desktop shell adds packaging complexity before the experience is proven.

Decision

Ship a local first: one Rust executable embeds the web assets, opens the browser, and serves the API. The same API runs in a hosted container later. A Tauri desktop shell, single binary installers and a hosted service are later deployment options, not v0 requirements.

Consequences

  • No Node runtime is required for the installed product.
  • The web UI is always the same; only the workspace location changes.
  • Offline use is a first-class path; no telemetry or cloud dependency for core features.
