ADR-0043 — Review a task branch from the topbar, and move finished tasks to In Review

  • Status: proposed
  • Date: 2026-11-27
  • Deciders: Benoit (to validate)
  • Amends: ADR-0029 (Start Work worktree), ADR-0040 (agents edit the task worktree)

Context

An agent finishes a task in its own worktree and commits on the task branch. The views (structure, code, changes) only read the main checkout, and changes are measured as git status against HEAD, so the committed work is invisible there. The task stayed “In Progress” after the run, and the user had to find the worktree by hand to compare it.

Decision

  • Review target. GET /api/review lists the main checkout, the task worktrees, other worktrees and local branches without a worktree. POST /api/review picks one (null returns to main). Picking a branch that has no worktree creates one under .fluid-coding/worktrees/, as Start Work does. The main checkout is never checked out or changed.
  • Views follow the target. While a target is set, the workspace snapshot is indexed from the worktree (active repo only), and the changes are measured against the base branch (main), including committed work. The task board and tags stay those of the main checkout, where status moves and tag writes land, so they are copied into the reviewed snapshot under its write locks.
  • Switching back. Choosing the main checkout, or switching project, restores the main snapshot.
  • In Review. When a run in a task worktree settles with an answer, its local task moves from In Progress to In Review. A task the user already moved during the run keeps that status. Failed runs leave the task In Progress.
  • Forge tasks follow their request. A GitHub or GitLab issue has no status written by the app (ADR-0023). The agent’s handoff asks it to push the branch and open a draft PR/MR that closes the issue. The board then reads the open request for the task’s branch: a draft means In Progress, a ready request means In Review, and a local branch with no request yet means In Progress while the issue is open. Closed issues keep their state.
  • The topbar switcher and the In Review task’s “Review”, “Review changes” and “Analyse run” actions all use this seam. Session analysis stays served by the active project’s trace store (ADR-0027): while a task worktree is under review, only the conversations recorded for that task are resolved, so the canvas shows the run that produced the branch and not unrelated sessions. Switching back to the main checkout removes the filter.

Consequences

  • Only the active repo is compared; other repos of a multi-repo project are left out while reviewing.
  • Forge status is derived when the board refreshes, so one extra open-requests read per refresh. A failed read keeps the issue’s own status and logs a warning.
  • The review target lives in memory, so a restart returns to the main checkout.
