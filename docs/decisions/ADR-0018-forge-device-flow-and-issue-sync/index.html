ADR-0018 — GitHub and GitLab device flow with issue snapshots

  • Status: accepted
  • Date: 2026-11-25
  • Amends: ADR-0016, ADR-0017
  • Amended by: ADR-0019, ADR-0023

Context

The task board declares GitHub and GitLab providers, but ADR-0016 only implemented PAT accounts and ADR-0017 only covered GitHub. A connected provider must retrieve real issues for the active repo, without exposing an OAuth token to the web layer or putting credentials in the repository.

Decision

  • GitHub and GitLab use OAuth 2 device authorization. GitHub reads FLUID_GITHUB_CLIENT_ID. GitLab reads FLUID_GITLAB_CLIENT_ID; FLUID_GITLAB_URL selects a self-managed instance and defaults to https://gitlab.com. GitLab device flow requires GitLab 17.9 or newer.
  • The browser only receives the one-time user code, verification URL, opaque poll id and public account. Access tokens stay in the existing 0600 forge token store and survive restarts.
  • GitHub requests repo; GitLab requests read_api. Both are read-only in fluid-coding even when a provider scope is broader. Remote issue status cannot be changed from the board.
  • GET /api/tasks refreshes the provider configured in project.settings.taskProviders when the active repo’s origin matches that forge. The manifest’s remoteUrl is the fallback when git cannot resolve origin.
  • GitHub pull requests returned by the issues endpoint are excluded. GitLab issues map iid, description, labels, assignees, milestone and timestamps to the shared Task contract.
  • A successful snapshot replaces that provider’s previous in-memory snapshot, so removed or closed issues do not remain visible. A remote failure is returned to the UI rather than shown as an empty board. The first 100 open issues are loaded; pagination and caching remain follow-ups.

Consequences

  • OAuth applications must be registered with device flow enabled. ADR-0019 bundles their public client ids in the app; FLUID_* variables remain optional overrides.
  • GitLab OAuth access tokens can expire; this slice does not yet persist or rotate refresh tokens. Reconnection is required after expiration.
  • The normalized remote tasks can produce a local Change Brief and start a local branch. ADR-0023 adds remote creation; update and status operations remain local-only.

Dogfood note

The flow was exercised against local HTTP doubles for both forges using this repository as the active-project shape: authorize, persist the public account/token split, fetch issues, normalize the board snapshot and generate the production web bundle. A live OAuth approval still requires the deployment client ids above.
