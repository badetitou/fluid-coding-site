ADR-0040 — Agents edit and run checks inside the task worktree

  • Status: proposed
  • Date: 2026-11-27
  • Deciders: Benoit (to validate)
  • Amends: ADR-0029 (Start Work trust), the “adapters never write repository files” note in crates/fluid-server/src/agents/mod.rs

Context

Start Work creates an isolated worktree and runs the Fluid Agent there (ADR-0029), but the agent could not do the task. A probe on 2026-11-27 with real CLIs in a scratch repository showed:

  • opencode run --format json (v2.4.2) has read, write, edit, shell, grep, glob, subagent, webfetch and writes files without --auto. Tool access was not the problem.
  • claude -p --output-format json (2.1.332) denies Write in its default permission mode: a headless run has no one to approve it. --permission-mode acceptEdits --allowedTools=Bash lets it edit and run commands. --allowedTools is variadic, so only the = form keeps the prompt intact.
  • The adapter prompt (agents/cli/prompt.rs) said “do not write files” in every trust mode and asked for hand-written JSON hunks. It also said “Use the read-only MCP tools for facts”, but no MCP server is passed (ADR-0031 is proposed). Replaying that prompt through opencode on a one-line task cost 33 tool calls spent looking for the missing tools, wrote nothing and returned a JSON patch.
  • Start Work always sent TrustMode::Propose, so the brief’s Check: commands and commit footer could not be acted on.

ADR-0007 already defines the modes: propose is a patch proposal, edit is a direct edit, auto is edit plus checks. The task worktree is the isolation those modes assume.

Decision

  1. Write access depends on the trust mode and on where the agent runs. The adapter resolves an access level from the request’s trust mode and its working directory:
    Working directory propose edit auto
    task worktree (Start Work) read-only edit edit + run
    main checkout or none (dock, intake) read-only read-only read-only
    The main checkout never gets write access, so the user’s uncommitted work is never touched.
  2. Read-only keeps the patch contract. The prompt asks for patches in the one-object JSON, as before, and tells the agent to read with its own read-only tools. The line about MCP tools is removed until ADR-0031 ships a server.
  3. Edit and edit + run work in place. The prompt says the cwd is an isolated worktree for the task: edit files there with the agent’s own tools, never touch files outside it, never push or switch branches. Edit + run also runs the brief’s checks, fixes failures, and commits on the current branch with the brief’s commit footer. The answer is the same JSON object with messages (what changed, check results) and no patches.
  4. Permission flags are per provider, added by the adapter. A pure table maps provider and access to extra argv inserted before the prompt. A flag already present in the user’s command wins; for Claude, any --permission-mode the user set also suppresses shell access.
    Provider Edit Edit + run
    claude --permission-mode acceptEdits --permission-mode acceptEdits --allowedTools=Bash
    opencode none (edits by default) --auto
    codex, copilot, ollama none (follow-up) none (follow-up)
  5. Start Work runs in auto. The brief carries Check: commands and a commit footer; the worktree is the review unit.
  6. Auto delivers a forge task as a pull request. For a GitHub or GitLab task, the agent pushes the task branch only (never force, never the base branch), opens a draft request after its first commit, pushes after each step, and marks the request ready for review once the checks pass and the work is finished. Local tasks get no request. This amends the “never push” rule of decision 3 for edit + run only; the request’s delivery rule is the only source of push permission.

Consequences

Positive:

  • A started task ends with real changes on its branch, checked by the brief’s commands.
  • The prompt no longer sends agents after tools that do not exist.
  • The dock and intake behave as before: read-only, patches only.

Negative:

  • Isolation is prompt-only. In edit + run, opencode --auto and Claude --allowedTools=Bash approve any shell command. The worktree lives at <repo>/.fluid-coding/worktrees/…, so the main checkout is ../.. from the agent’s cwd: an agent can still write there or git push. The prompt forbids it; nothing enforces it. A git worktree is not a sandbox.
  • In edit (no run), opencode’s default permissions still allow shell; “do not run commands that change state” is enforced for Claude only. No caller uses edit today: Start Work sends auto.
  • Work done in the worktree does not appear in Review’s patch list; users open the worktree or its branch. Showing the worktree diff in Review is a follow-up.
  • Codex (codex exec is read-only by default) and Copilot (copilot -p needs tool approval) still cannot write; their flags must be verified against installed CLIs before they are added.

Alternatives considered

  • Keep patches only and apply them automatically in the worktree. Rejected: the agent still cannot run checks against its change, and hand-written hunks with exact old lines are fragile.
  • Always pass --dangerously-skip-permissions / bypass mode. Rejected: broader than needed and would also apply to the dock in the main checkout.
  • Wait for the MCP server (ADR-0031). Rejected: MCP gives facts and proposals, not file edits or shell; the agents’ own tools already do that.
