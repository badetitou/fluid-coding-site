ADR-0046 — Session analysis falls back to the chat transcript

  • Status: proposed
  • Date: 2026-11-27
  • Deciders: Benoit (to validate)
  • Amends: ADR-0027 (GenAI trace model), ADR-0028 (session analysis rendering)

Context

GET /api/session-analysis built its graph only from OTLP spans in .fluid-coding/traces/. In practice only opencode exports spans, and their ids do not name the chat they belong to, so every conversation opened from the dock showed a lone session node: no turns, no tool calls, no sub-agents. Each ChatTurn already stores the run’s ToolActivity list in order, and a sub-agent call (Claude’s Task, opencode’s subagent) carries its own nested AgentTranscript.

Decision

  1. The transcript is a span source. Pure fluid_core::session_graph::transcript_spans turns a ChatSession into the span tree the graph already reads: one chat span per turn, one execute_tool span per call, and a nested invoke_agent span per sub-agent with its calls under it. Spans carry fluid.source = transcript, ids <chat>-t<n> (stable as the transcript grows, and valid expand ids), and the call’s input preview as contentRef.
  2. Telemetry wins when it exists. The route uses the transcript only for a chat that matched no recorded span. No timing is invented: transcript spans have increasing synthetic start times and a zero duration, so order is real and the duration totals stay honest.
  3. Calls after a sub-agent stay with their caller. The layout closes a sub-agent’s tool batch as soon as a call whose parent is outside it arrives, so the caller’s later calls get their own batch instead of being counted inside the sub-agent.

No wire type changes; the contracts and fixtures are untouched.

Consequences

  • Every agent (Claude, fluid, opencode, Codex) shows its turns, calls and sub-agents, live while the turn is pending, without any telemetry setup.
  • Durations and tokens appear only for runs that export telemetry.
