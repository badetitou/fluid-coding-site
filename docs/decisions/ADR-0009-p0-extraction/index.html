ADR-0009 — Behavior-preserving platform extraction from fluid

  • Status: accepted
  • Date: 2026-11-24

Context

fluid-coding needs fluid’s ViewSpec engine, widgets, plugin host and UI primitives. Copying them creates two divergent engines. Blocking on a big-bang extraction risks breaking fluid, which is already published as a CLI and container images.

Decision

Extract shared packages first, in the fluid repository, behavior-preserving. Order: contracts → engine ports (QueryRunner, NavigationPort, theme injection) → engine move → widget collections → plugin host → UI kit → MCP/CLI kits → release. fluid stays shippable at every step.

Consequences

  • fluid-coding consumes @badetitou/fluid-* via file:/workspace, then semver.
  • No engine file moves before the fake-data harness proves the ports.
  • Each stage has an explicit acceptance check and a rollback path.
  • The extraction is a prerequisite for M0, not a parallel rewrite.
