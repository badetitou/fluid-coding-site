ADR-0048 — The analysis canvas is a linked tree, down or right

  • Status: proposed
  • Date: 2026-11-27
  • Deciders: Benoit (to validate)
  • Amends: ADR-0028 (session analysis rendering)

Context

Children were laid out under their parent while edge handles sat on the left and right, and the only edges were tool batches drawn from one turn to the next: most nodes floated with no line to where they came from. A sub-agent’s grandchildren (an inner turn’s batch) were placed below its box, so dragging the box left them behind, and an open batch’s tool rows did not follow their batch. An open batch also showed 8 calls and counted the rest as dropped.

Decision

  1. Every node is linked. Calls arrive on an aggregated edge into their tool batch or MCP server; every other node gets a plain link (callCount: 0) from its parent. A node drawn inside its parent’s box (a sub-agent’s direct child, an open batch’s tool rows) has no line.
  2. Containers hold their subtree. The layout places a sub-agent’s whole subtree inside its box, grows the box to fit once the subtree is placed, and moves it right if it then covers another node. On the canvas, a node’s React Flow parent is its nearest container (sub-agent or open batch), with extent: 'parent', so it moves with the box and cannot leave it.
  3. Two directions. GraphOptions.direction (down | right, default down) is laid out by the core: the tree is computed along one axis and turned for right, tool rows staying a list down their batch. SessionGraph.direction echoes it and the canvas puts handles on the matching sides (bottom→top or right→left). The page keeps the choice in the URL (layout=right).
  4. Open batches show their calls. The route defaults to 1 000 nodes and 200 rows per open batch (bounds 2 000 and 500). Edge intensity uses a fixed 8-call scale instead of the row limit.

Contract: direction is added to GraphOptions and SessionGraph in Rust and zod, defaulting to down, so older payloads still parse.
