ADR-0039 — Analysis delta compares the change with its merge target

  • Status: proposed
  • Date: 2026-11-26
  • Deciders: Benoit

Context

The Structure page (“The shape of the change”) already shows the current ModelAnalysis: cycles, self-calls, isolated entities, degrees and relation counts. Those are absolute numbers. The user asked for the delta of the change: did this work add cycles, isolated classes or relations?

A delta needs a reference. The interesting reference for a branch that wants to be merged is the branch it targets in an open PR/MR, not necessarily main and not the current HEAD. The forge adapters already expose ForgeReviewSummary.source_branch and target_branch for connected GitHub/GitLab accounts, but the analysis route did not use them. The app has no account-per-repo binding yet, and a forge lookup can fail or be slow; no number may be invented in that case.

Decision

  1. GET /api/model/analysis returns the existing ModelAnalysis plus baseline and delta. baseline is { source: 'review' | 'head' | 'none', ref: string | null, note: string | null }; delta holds signed integers for cycles, cyclic entities, self-calls, isolated entities, entities and relations. delta is null when no baseline could be inspected.
  2. Baseline selection happens on the server, once per index generation:
    • current local branch → open PR/MR target branch from the connected forges (3 s timeout, deterministic choice when several reviews match);
    • otherwise HEAD;
    • otherwise none, with the reason in baseline.note. A review ref is resolved through origin/<target> before the local branch so a stale local branch cannot stand in for the merge target.
  3. fluid-index::analyze_baseline exports the tracked tree of that commit with git archive into a temporary directory, indexes it with the same plugins and runs the same model-analysis engine as the live graph. No git worktree is added and the user’s checkout is never modified. Unsafe refs, missing git, failed archive/extraction and unresolvable refs are typed errors; the route then falls back to HEAD or to a none baseline.
  4. The browser only formats the signed counters. It never builds a second graph or recomputes a count. The wire contract is validated by zod (modelAnalysisResponseSchema) and by the shared fixture on both sides.
  5. Baseline resolution and indexing are cached in the workspace snapshot alongside the current analysis, so opening the section or re-rendering it costs at most one forge lookup and one baseline index per generation.

Consequences

Positive:

  • The Structure Analysis section answers “what did this change add?” for a real PR/MR target, and remains honest when there is no forge review, no git or no readable baseline.
  • The delta uses the same canonical engine as the absolute numbers, so cycles and isolated entities are comparable by construction.
  • The checkout and the forge tokens stay untouched; only a branch name and a ref reach the client.

Negative:

  • A baseline costs a second git archive, extraction and index, off the async runtime and only on first Analysis open. The 100k LOC p95 budget still has no measured baseline (ADR-0033); this path must be included when that bench lands.
  • Several connected forge accounts may be queried because the project has no account-per-repo binding. The lookup is time-boxed and cached; a branch-name collision across accounts is resolved deterministically but may not be the project’s own PR.
  • A stale remote tracking ref can differ from the live forge target until the next fetch. The response names the ref but not the target commit.

Alternatives considered

  • Snapshot the previous analysis locally. Rejected: no baseline exists before the first open and it would compare sessions, not the change being reviewed.
  • Use git diff HEAD only. Rejected: it ignores commits already pushed to a PR/MR branch.
  • Index the baseline with a git worktree. Rejected: it mutates .git/worktrees for a read-only question and needs cleanup on failure; git archive is read-only.
  • Resolve the PR target in React. Rejected by AGENTS.md: domain decisions stay behind the Rust server and the typed port; the client only renders.
