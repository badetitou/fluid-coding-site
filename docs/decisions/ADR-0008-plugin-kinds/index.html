ADR-0008 — Typed plugin kinds, SDK and sandboxing

  • Status: accepted
  • Date: 2026-11-24

Context

fluid already has themes, widgets, view builders, source providers, page actions and graph decorators. fluid-coding needs code analyzers, checks, agent providers, workspace providers, change presenters, tag kinds and language providers. A loose “plugin” interface would make quality and security impossible.

Decision

Define explicit plugin kinds with typed contracts, manifest versioning and contract tests. First party collections ship as plugins (fluid-code-map, fluid-review, fluid-tags, fluid-agents, fluid-code-graph, fluid-pharo). Third-party analyzers run in a sandbox (WASM component or worker), and agent providers require explicit consent and credentials isolation.

Consequences

  • The plugin manifest is a versioned contract, not an arbitrary module.
  • A broken plugin must fail in isolation, never take down the workbench.
  • New plugin kinds require an ADR or a contract proposal, tests and docs.
