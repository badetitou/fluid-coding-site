ADR-0035 — Task intake: explain an issue to the agent, then create it

  • Status: accepted
  • Date: 2026-11-26
  • Depends on: ADR-0011 (task tracking), ADR-0023 (forge issue creation), ADR-0024 (Fluid Agent)

Context

Creating an issue on the Board meant writing a title and a Markdown body by hand, then splitting the work into tasks in a separate step. The user wants to describe the goal in conversation and get the issue and its tasks drafted for them. The Fluid Agent already runs the configured CLI behind AgentPort, so the intake can reuse it.

Decision

  1. The agent proposes; the user creates. POST /api/tasks/intake takes the transcript and returns { reply, draft }. draft is null while the agent still asks questions. Nothing is written by the intake route.
  2. One JSON object per reply. The prompt asks for a single JSON object. The server reads the first { to the last } and validates it: a non-blank reply, a non-blank title, non-blank sub-tasks. Anything else is a typed 400 error, never a silent default.
  3. Creation reuses POST /api/tasks. On submit the web client creates the issue with the normal routing (auto: connected forge, else local). Forge routing, validation and errors stay in one place.
  4. Sub-tasks depend on the target. Forge issues have no sub-task API yet (ADR-0023), so the sub-tasks are written as an unchecked checklist in the body. Local tasks also get real child tasks through parent. On the local kanban the checklist and the child tasks both appear; that is the known cost of not knowing the target before creation.
  5. Bounded transcript. At most 40 messages of 8 000 bytes each, ending with a user message.

Consequences

  • Intake quality depends on the selected CLI following the JSON shape. A non-conforming reply is reported as an error in the chat; the user can retry or fill the form by hand.
  • The intake runs in the active project root, or the server working directory when no project is configured.
  • Forge sub-tasks, a dedicated contract fixture and a live CLI run are not covered yet; they should follow once a forge exposes sub-issues.
