ADR-0026 — Ollama is a selectable local LLM provider

  • Status: accepted
  • Date: 2026-11-26

Context

General settings offer four machine-level LLM providers, and the Fluid Agent follows that selection (ADR-0024). Developers running models locally with Ollama had no entry in the list, so they could only reach it by repurposing another provider’s command override. Ollama’s CLI is a plain one-shot command (ollama run <model> <prompt>); it has no JSON output flag like the four original providers. A hard-coded model name would be a guess and would break on machines with different local models.

Decision

Add ollama as a fifth stable provider id in the Rust PROVIDERS table and in the shared zod llmProviderIdSchema. Model names come from the user’s own Ollama daemon: the server adapter reads GET /api/tags (OLLAMA_HOST, default http://127.0.0.1:11434), deduplicates and sorts the names, and exposes them on the provider view. The settings UI offers those names in a select; the first one is the proposed default until a choice is saved. Saving writes ollama run <model> as the provider’s command override, so the last chosen model is remembered in ~/.fluid-coding/general-settings.json and the agent never re-discovers models at run time. With no installed model there is no default command and the dock reports the missing model instead of running a guessed one. Detection, validation, persistence and agent dispatch keep using the same generic provider path: no special case is added to the settings route, the dock or the CLI adapter. Plain-text output is surfaced as an agent message by the existing CLI mapping. This qualifies ADR-0024’s “JSON-capable commands for all four providers”: that statement covers the four original providers only.

Consequences

  • Ollama appears in Settings → General with a Detected badge when ollama is executable on PATH and a model select populated from the local daemon. A stopped daemon means an empty list, not an invented model; the HTTP probe is best-effort and never blocks settings for more than two seconds.
  • Selecting Ollama and saving remembers the first installed model. Changing the select and saving remembers the last chosen one. Picking a model rewrites the command from the provider template, so custom flags in a manual override are replaced.
  • A saved model that is no longer installed stays in the command and the CLI reports the error; the select shows the first currently installed model. Refreshing the page re-reads the daemon.
  • Ollama does not emit the agent JSON object by default, so patch proposals require a model that follows the documented JSON contract. Text answers still appear in the dock.
  • The contract change is mirrored in the mock settings fixture and covered by tests on both sides.

Dogfood note

The adapter was checked against the daemon running on this machine: GET /api/tags returns real names such as qwen3.5:9b-mlx and gemma4:26b-mlx, which the parser accepts and sorts. The app proposes gemma4:26b-mlx first here instead of any hard-coded model.
