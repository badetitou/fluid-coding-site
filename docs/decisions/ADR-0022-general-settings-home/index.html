ADR-0022 — General settings live in the user’s fluid home

  • Status: accepted
  • Date: 2026-11-25
  • Amends: ADR-0021

Context

PATCH /api/settings/general failed in the installed macOS app with general settings I/O error: Read-only file system (os error 30). home_from_environment() resolved the settings file to FLUID_WORKSPACE/.fluid-home or, when the welcome window opened without a workspace, to ./.fluid-home. An .app launched from Finder starts with / as its working directory; on a sealed macOS system volume that directory is read-only, so create_dir_all failed before any settings were written.

Forge secrets (~/.fluid-coding/forge) and the project index (~/.fluid-coding/projects.json) already resolve from FLUID_CODING_HOME or HOME. Machine-level settings were the outlier: they were tied to a checkout or to the current directory, even though an LLM choice and a theme are properties of the machine, not of a project.

Decision

The general settings file resolves to:

  1. FLUID_CODING_HOME/.fluid-coding/general-settings.json when the variable is set;
  2. HOME/.fluid-coding/general-settings.json otherwise;
  3. <FLUID_WORKSPACE>/.fluid-home/.fluid-coding/general-settings.json when neither variable is available;
  4. ./.fluid-home/.fluid-coding/general-settings.json as the last resort.

The path is resolved once in AppState and passed to the settings routes; request handlers no longer read the working directory or resolve environment variables into a path. I/O errors name the path that failed, and a failed write returns 500, not 400.

Consequences

  • Saving General settings works in the installed macOS app, with or without a configured project, and never writes into a checkout.
  • Resolution is a pure function with tests for the override, user-home and workspace fallbacks.
  • Route tests inject their own AppState, so they cannot read or overwrite a developer’s real settings.
  • Settings written to the old locations are not migrated. A tester may need to choose the provider, theme and rail position once again after upgrading; as in ADR-0021 this prerelease has no migration step.
  • FLUID_CODING_HOME remains the single override for relocating user state and for test isolation.
