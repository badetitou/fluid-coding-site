ADR-0041 — Agent runs stream their tool calls and text into the conversation

  • Status: proposed
  • Date: 2026-11-27
  • Deciders: Benoit (to validate)
  • Amends: the AgentPort seam in crates/fluid-core/src/plugins/agent.rs (adds a default method)

Context

The dock ran an agent with a blocking request and showed “Working… the answer appears here when the run finishes”. The CLI adapter read the whole stdout only after the process exited, so the user saw neither the tool calls nor the text while the agent worked. Start Work already ran in the background and polled its pending conversation (ADR-0029), so the transcript could hold a turn that fills in.

Decision

  • AgentPort gains run_with_progress(request, progress). Its default calls run and reports nothing, so adapters that cannot stream keep their behaviour.
  • The CLI adapter reads stdout line by line and turns each line into AgentEvents (text fragments, tool start, tool result). Claude runs use --output-format stream-json --verbose --include-partial-messages, added when the command asks for json or names no format. opencode’s --format json events are read as they come.
  • A run started with POST /api/agents/{id}/start returns its conversation id at once. Progress is folded into the pending turn (RunProgress: text segments and tool calls) and written in batches. The client reloads that conversation until the turn settles. Settling replaces the streamed text with the parsed answer and keeps the tool calls.
  • Tool calls are stored on the turn (ChatTurn.tools) with a preview of their input and output, clipped to 2,000 characters.
  • Sub-agents: Claude marks the output of a sub-agent with parent_tool_use_id. That output becomes AgentEvent::Nested and is stored under the call that started it (ToolActivity.run, an AgentTranscript), recursively. The dock shows a breadcrumb path to reach it; the path is kept as tool ids and ends where an id no longer exists. opencode runs a sub-agent in its own session, whose events are not in the run’s stream. The adapter records each sub-agent’s session from the subagent call’s metadata; once the run has ended it reads that session back with opencode session export <id> and nests its text and tool calls under the call. So opencode sub-agents appear when the run ends, not while they run. Reading them live would mean polling the export during the run; not done.
  • The one-object answer contract is not shown while it streams: a segment that starts with { or a code fence is hidden until the run settles.

Consequences

  • The synchronous POST /api/agents/{id}/run stays for callers that want the whole response at once.
  • Polling is the transport: the client reads the conversation every 600 ms while a turn is pending. Server-sent events would remove the polling but need a second transport; not done here.
  • Only Claude and opencode stream. Codex and Copilot still answer at the end.
  • The stream formats of the CLIs are external: a format change makes progress go quiet, but the final answer still comes from the full stdout, so no run loses its result.
