ADR-0044 — Agent questions are answered in the dock

  • Status: proposed
  • Date: 2026-11-27
  • Deciders: Benoit (to validate)
  • Extends: ADR-0042 (opencode runs through opencode serve) and ADR-0041 (streamed runs). AgentPort is unchanged; AgentEvent gains one variant.

Context

opencode’s question tool lets the agent ask the user something mid-run. The run waits for the answer. A streamed run in the dock had no way to show the question or send an answer back, so the run stayed at “running” with no output (reported 2026-11-27).

The live server (opencode serve, v2.4.2) reports the question as a form (probed locally):

  • session.tool.called for the call question, whose input holds the questions;
  • form.created with metadata.kind = "question", metadata.tool.id (the call), and fields: each field has a key, a title (header), a description (the question), type string (one choice, or typed text when custom) or multiselect, and options (value, label, description);
  • POST /api/session/{id}/form/{formID}/reply with {"answer": {key: value | value[]}} settles it. The run then continues with session.tool.success and finishes.

The Claude stream-json path runs with stdin closed and has no answer channel, so it is out of scope for this decision.

Decision

  1. Event. AgentEvent::Question { tool, question } attaches an AgentQuestion to the call that asked it. The transcript stores it on ToolActivity.question, so it survives a reload. The question is shown while the call is running.
  2. Mapping. Only kind = "question" forms become questions. string and multiselect fields map to items; other field types are left out with a logged warning.
  3. Answer route. POST /api/agents/runs/{conversationId}/answer takes a QuestionAnswer (questionId, answer keyed by item key). It hands the answer to the run waiting under that conversation and returns { answered }. answered: false means no run is waiting (it finished, was stopped, or never asked), so the dock shows the question as closed.
  4. Run. The opencode run keeps the question form open until an answer for it arrives. It then replies to that form. An answer for a form that is not open is ignored, so a stale click cannot end the run. A stop still ends the server and the run as before.
  5. Dock. The question card sits under the running question call. It submits every item at once. The card disappears when the call settles.
  6. Not covered. Claude Code runs, runs without a conversation id, and questions of other types (boolean or number fields) are not answerable here. A boolean field is left out, so the agent may still wait for an answer it never gets; the run then stops only when the user stops it.

Consequences

  • An agent that asks a question now waits for the user instead of hanging silently.
  • The answer goes to the server over loopback, like the other run calls; nothing is stored in the repository.
  • Blocking a question instead (disabling the tool for runs) remains possible later if answers prove too costly; it would be a new ADR superseding this one.
