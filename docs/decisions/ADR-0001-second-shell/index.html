ADR-0001 — fluid-coding is a second shell on a shared platform

  • Status: accepted
  • Date: 2026-11-24

Context

fluid already has a ViewSpec engine, widgets, a plugin host, a BFF and a CLI. fluid-coding needs the same rendering, plugin and packaging primitives, but a different domain: code, structure, changes and agents. Forking or vendoring fluid would duplicate the engine and split every future improvement.

Decision

Build two shells on one core: fluid (data) and fluid-coding (code). Shared capabilities move into @badetitou/fluid-* packages. Each shell owns its domain services and its home experience.

Consequences

  • The platform extraction (ADR-0009) precedes the coding UI.
  • The shells can evolve independently but share contracts, engine and plugin host.
  • A change to the engine requires a compatibility check in both shells.
