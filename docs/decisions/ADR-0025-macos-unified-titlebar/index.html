ADR-0025 — Fuse the web topbar with the macOS title bar

  • Status: accepted
  • Date: 2026-11-26

Context

The installed app opens a tao window with a wry WKWebView. The default WindowBuilder draws a native title bar (traffic lights plus a centred title) above the web TopBar, so the window shows two stacked bands.

VS Code, Claude Desktop and current OpenCode Desktop get a single band by hiding the native title bar and rendering their own in the renderer, with Electron’s -webkit-app-region: drag providing window movement. WKWebView does not implement that CSS property, and adopting Electron/Chromium would break the Rust-first, low-footprint shell.

Decision

Keep tao + wry and reproduce the two halves of the Electron trick locally:

  • crates/fluid-cli/src/native.rs builds the window with with_titlebar_transparent(true), with_title_hidden(true), with_fullsize_content_view(true) and an explicit traffic-light inset. The webview is transparent so the themed topbar paints the whole band.
  • crates/fluid-cli/src/drag.rs adds a transparent NSView over the full 52pt band. Its mouseDown: calls performWindowDragWithEvent: (or performZoom: on double-click), which is what Electron does behind app-region: drag. Traffic-light buttons stay above the strip and remain clickable. The web publishes the rects of topbar controls over window.ipc; the strip’s hitTest: returns nil for those rects, so the controls keep their clicks while the rest of the band moves the window.
  • On each finished page load, the shell marks <html> with data-shell="mac" and data-fullscreen; apps/web/src/styles.css gives the topbar the full window width and indents its controls past the lights, so the title sits beside them. The rail starts below the topbar instead of painting under the lights. The browser build keeps its plain 52px topbar.

No protocol, generated contract or React state changes: the marker lives on the root element and CSS is the only consumer.

Consequences

  • The native title string disappears and the traffic lights sit inside the themed topbar band, with one continuous surface instead of two.
  • Window movement and double-click zoom still work without a Chromium runtime.
  • The strip covers the whole topbar band except the published control rects; dragging works from empty topbar space and the controls stay clickable. In fullscreen the strip is hidden and the CSS indent drops via the data-fullscreen marker, because AppKit hides the controls.
  • Traffic-light appearance follows the system theme, not the six in-app themes. Syncing window.set_theme() with the saved theme is a possible follow-up, not part of this decision.
  • Drag, zoom and the CSS safe area need a manual check in the installed .app; the URL classifier, marker JS and strip geometry are unit-tested.
