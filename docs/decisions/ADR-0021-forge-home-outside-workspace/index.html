ADR-0021 — Forge secrets live in the user’s fluid home

  • Status: accepted
  • Date: 2026-11-25
  • Amends: ADR-0016

Context

ADR-0016 required forge tokens to live outside the project repository, but forge_home(workspace) resolved to <workspace>/.fluid-home/forge when FLUID_CODING_HOME was unset. When the workspace is the repository itself, that path is inside the repository, so sign-in could fail while creating the secret store and tokens would be mixed with project files. The project index and setup state already use ~/.fluid-coding; forge state was the outlier.

Decision

forge_home resolves to:

  1. FLUID_CODING_HOME/.fluid-coding/forge when the variable is set;
  2. HOME/.fluid-coding/forge otherwise;
  3. <workspace>/.fluid-coding/forge only when neither variable is available.

The workspace fallback is a last-resort test path, not the installed-app path. Directory creation errors now name the resolved path, so a failed sign-in reports where it tried to write.

Consequences

  • Access tokens and account metadata stay with the user’s other fluid-coding state and outside every checkout, including when no FLUID_CODING_HOME is configured.
  • Existing tokens under <workspace>/.fluid-home/forge are not migrated; those accounts must be reconnected once. This prerelease has no account migration.
  • FLUID_CODING_HOME remains the single override for user-home relocation and test isolation.
  • The path rule is unit-tested; the 0600 token file and 0700 token directory behaviour from ADR-0016 is unchanged.
