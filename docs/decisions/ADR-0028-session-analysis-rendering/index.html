ADR-0028 — Render session analysis with a lazy React Flow canvas

  • Status: accepted
  • Date: 2026-11-26

Context

The user wants to zoom, drag nodes, collapse chat turns and expand subagent groups in one canvas. The structure map uses a custom canvas because it has its own cells and interaction model, but a session graph adds viewport transforms, hit-testing, port edges, parent groups and selection. Drawing that from scratch would reimplement what a graph-viewport library already provides, and would put graph semantics in React against the performance rules.

Decision

  • Use @xyflow/react v13 (React Flow 13) for the analysis surface. It is imported only from the lazy /analysis?ids=... route under Shell, together with its v13 stylesheet; it is never an eager import in the coding shell. There is no new primary nav item: Agents opens the route for one session or a multi-selection.
  • React Flow supplies the viewport, dragging and hit-testing. Nodes and edges are custom components: session, turn, toolBatch, tool, subagent, exception and message nodes, with nested spans as expandable parent groups and breadcrumbs. Consecutive execute_tool spans between two turns collapse into one arrow per segment; stroke width and colour intensity encode callCount, and clicking expands bounded pages of underlying nodes.
  • Layout is computed once in the pure fluid-core builder: positions, sizes, lanes and expansion state arrive on GraphNode. The client renders that result and never recomputes graph semantics.
  • One GET /api/session-analysis?ids=...&expand=... request serves the whole selection; the web client validates the response with the shared zod schema.
  • Keep React Flow’s default attribution (no Pro), import its CSS only in the lazy module, and layer app styles explicitly so the late stylesheet does not override shell tokens.
  • Use onlyRenderVisibleElements and memoized node/edge components; URL state carries the selected ids and expanded span ids.

Consequences

  • The React Flow chunk is expected at roughly 64–86 KiB gzip (estimate, not measured yet) and stays outside the 150 KiB initial JS budget. The exact size is recorded in the PR when the chunk lands.
  • A 300-visible-node canvas must hold 60 fps pan/zoom; the gate and its Playwright rAF trace are in the budget doc and are not measured yet.
  • Custom nodes and edges keep the canvas free of domain logic, but the v13 CSS import order needs a visual check in both the dev server and the installed app.
  • Collapsed batches and parent groups keep the canvas legible without extra requests; expansion is bounded by maxNodes and maxCallsPerBatch in the shared graph options.
  • Metadata-only traces by default mean nodes show timing, errors and call counts; prompt and tool payloads appear only when content capture was explicitly enabled.
