ADR-0045 — Task intake streams its durable run into Now

  • Status: accepted
  • Date: 2026-11-27
  • Deciders: Benoit (to validate)
  • Amends: ADR-0035 (task intake chat), ADR-0038 (shared chat field), ADR-0041 (streamed agent runs)

Context

ADR-0035 made the intake a single blocking POST /api/tasks/intake that returned { reply, draft } once the agent finished. Now showed a “Thinking” indicator during that wait, so tool calls and text produced by the agent were invisible until the answer arrived. The dock already had the pieces needed to show a run while it works: settle_background_run folds AgentEvents into a pending ChatTurn, and AgentActivity renders that turn’s text, ToolCalls and sub-agent Breadcrumbs. The dock polled that turn with its own 600 ms timer (ADR-0041), and ADR-0038 deliberately kept the two flows independent.

Decision

  1. The intake starts a durable run. POST /api/tasks/intake validates the transcript as before, creates a conversation, registers its pending turn, spawns settle_background_run and returns { conversationId, agent } immediately. The request still fixes TrustMode::Propose, task_key = "task-intake", no files and the 40-message / 8 000-byte transcript bound. The run uses root: None, so it never moves a task to review, and it writes nothing to the Board. The conversation title is the user’s last message, not the prompt’s instructions.
  2. One result endpoint, one parser. GET /api/tasks/intake/{conversationId} returns the settled { reply, draft }. Rust parse_reply remains the only parser of the answer contract; the web client only validates the zod mirror. A still-pending turn is a 400, a failed or stopped turn is a 502, and an unknown id is a 404. The added conversationId lives on the start response; the final answer keeps the ADR-0035 fields. POST /api/tasks and the draft card are unchanged.
  3. One polling hook. hooks/usePendingTurnPolling.ts owns the 600 ms timer, the once-only settle announcement and the error path. useAgentWorkbench (dock and Start Work) and both intake surfaces (useTaskComposer for Now, TaskIntakeChat for the Board form) call it. No page owns a second timer, and the same ChatSession client reads every run.
  4. Now shows the live turn. While a turn is pending, NowChat renders AgentActivity with the streamed text, tool calls and breadcrumbs in place of now-typing. The short transcript omits the latest user turn while it is shown inside that activity, so no message is duplicated. The ⌘/Ctrl+Enter shortcut, the disabled mode/context chips and the draft card stay as in ADR-0038.
  5. Failure is honest. A failed or stopped run settles its turn as an error. The client restores the typed message, drops the unfinished user turn, clears the live activity and shows the error. Partial streamed text can never become a draft; only the parsed settled reply can.

Consequences

  • The intake now appears in the dock’s durable history, because every run is a ChatSession under .fluid-coding/sessions/. This is visible but inert: Now does not gain dock tabs or a session list, and it never selects the dock’s active conversation. ADR-0038’s “no shared active id” still holds; only the polling transport and the rendering components are shared. The ADR-0038 consequence “no new endpoint or store” is superseded by points 1 and 2 above.
  • A client that only understands the old single-shot response must call the new result endpoint after the turn settles; both web surfaces do so through the shared hook.
  • Polling stays the transport for now (ADR-0041). SSE would remove the timer but needs a second delivery path, so it remains out of scope.
  • The result endpoint reads the settled text, which includes narration before the last tool call. parse_reply already finds the answer object in surrounding prose; the answer contract is hidden from the live view while it streams.
  • Contract fixture fixtures/contracts/task-intake.json now carries request, start and reply shapes, parsed in both Rust and TypeScript tests.

Alternatives considered

  • Keep the blocking request and stream by SSE. Rejected: it would duplicate the dock’s durable run machinery and add a transport the project does not use yet.
  • Parse the pending turn in React. Rejected by ADR-0035 and rule 6: parse_reply stays in Rust so there is one answer contract and one validation path.
  • Give Now a copy of the dock’s workbench. Rejected: Now keeps its own reducer and draft card; sharing state would reintroduce tabs, history and patch actions on the intake surface.
