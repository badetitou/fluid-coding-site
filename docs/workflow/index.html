User workflow — from a sentence to main

Target loop for the user’s daily work in fluid-coding: describe a task in chat, validate the proposed issue, let an agent work it in an isolated worktree, review the result, then integrate into main. Status is kept current in the last section; the diagram is the target, not the current state.

flowchart TD
    A([Chat: user describes the goal]) --> B[Agent proposes issue + sub-tasks<br/>as a draft card]
    B -->|Discard| A
    B -->|Create task| C[(Board: Todo)]

    C --> D{User chooses}
    D -->|Start work| E[Agent runs in task worktree<br/>.fluid-coding/worktrees/]
    D -->|Set autowork| F[Autowork flag on the issue]

    F --> G{Every X minutes: any agent running?}
    G -->|no| H[Take next autowork issue<br/>queue order]
    G -->|yes| G
    H --> E

    E --> I[Agent finishes:<br/>patch proposed in the worktree]
    I --> J[(Board: In Review)]

    J --> K[Inspect the worktree in fluid-coding<br/>structure, model, diff, session analysis]
    K --> L{Decision}
    L -->|Comment in chat| M[Comment sent to the agent]
    M --> N[Issue back to In Progress]
    N --> E
    L -->|Validate| O[Integrate into main]
    O --> P([Done])

Steps and where they live

# Step Target behaviour Status Where
1 Chat describes the goal Free text in a chat composer Done Home composer, Board create form (ADR-0035)
2 Proposed issues as graphical cards, validate or not Draft card with Create / Discard; sub-tasks shown Done TaskDraftCard, POST /api/tasks/intake
3 Tasks land in Todo Created on the connected forge, else local board Done for creation; local file persistence partial ADR-0023, local_save.rs, STATUS Next 5
4.1 Start work: agent proposes a solution Worktree per task, agent run, patch proposed Done ADR-0029
4.2 Set autowork; queue picks next issue when no agent runs Autowork flag, polling loop, single-agent queue Not started —
5 Done agent work goes to Review; inspect the worktree in-review status; inspection with structure, model, diff, sessions Done: the review card sets the worktree scope used by Structure, Changes and session analysis (ADR-0043) TaskStatus::InReview, ADR-0028, useReviewTask
5.1 Comment in chat, issue returns to In Progress Comment on a review task re-runs the agent in the same worktree Done for local tasks: the comment box on an In Review task re-runs the Fluid Agent in the task worktree (POST /api/tasks/{key}/comment); inline diff comments are out of scope task_comment.rs, TaskReviewComment
6 Validate, integrate into main Merge the task branch into main, clean the worktree Not started (worktrees are never removed automatically, see ADR-0029) —

Blockers and risks found by the workflow trial:

Problem Issue
Intake fails without a provider and hangs on a slow agent (step 1) #13
Start work refused after the project is activated (step 3) #14
Server can start work in another checkout when FLUID_WORKSPACE is set (step 0) #15

Decisions

  • Autowork is global. One agent slot for the whole app in v1: the queue starts the next autowork issue only when no agent is running anywhere. Per-project slots can come later by changing the queue key.
  • Review stays in the existing pages. No new navigation item. A task in review opens Structure, Changes and session analysis scoped to its worktree. A worktree selector in the topbar switches the scope, so the same pages serve the main checkout and any task worktree.
  • Integration. A local task merges into main with git merge --no-ff, so each task keeps a visible merge commit. It runs only on an explicit Validate click, and only when the main checkout is clean. A forge task opens a PR instead; the review happens on the forge (ADR-0016).
