First-run setup

A fresh app opens on /setup instead of the map. Setup has two front doors that produce the same reviewable proposal:

  • Guided — name, root path, repository rows, language checkboxes, plugin checkboxes and trust mode.
  • Chat — “I want to work on fluid at ~/dev/fluid”. An LLM may help parse the sentence, but the deterministic filesystem scan is the source of truth.

See ADR-0015.

What setup does

  1. Reads the local project index (~/.fluid-coding/projects.json) and the plugin registry.
  2. Scans the chosen directory: .git, package.json, tsconfig.json, pom.xml, *.tonel, README.
  3. Proposes a project with one row per repository, language providers and plugin choices with reasons.
  4. Lets the user edit the proposal, answer questions and enable extra permissions explicitly.
  5. On Apply, writes .fluid-coding/project.json, updates the index, activates the project and opens the map.

Safety

  • Nothing is written before Apply. The default trust mode is propose.
  • Paths from chat are untrusted text: they must resolve to an existing directory.
  • Plugin ids are checked against the registry; hallucinated ids are dropped with a warning.
  • network:out and process:spawn permissions require a separate checkbox.
  • If the LLM is unavailable or returns invalid JSON, setup still works offline.

Setup can be reopened from Settings at any time. Adding a repository later is the same flow: edit the project definition or rerun setup and merge the proposal.
