First-run setup

A fresh app opens on /setup, a dedicated Connect this project screen for the real local workspace the app was launched against — not a generic navigation tab. Two refine modes produce the same reviewable proposal:

  • Guided form — checkboxes and dropdowns, seeded from detection: name, root path, repository rows, languages, plugins and trust mode.
  • Chat — “Refine this project: add the API repo”. The sentence only refines wording and choices.

The deterministic filesystem scan is the source of truth for paths, repositories and languages. An LLM may suggest a project name or plugin reasons, but it never supplies a path and never overrides a filesystem fact.

See ADR-0015.

Workspace detection order

GET /api/setup/status reports detectedWorkspace:

  1. Canonicalize the launch directory: FLUID_WORKSPACE when set, otherwise the process current directory.
  2. Check that directory, then at most ten parents. Prefer the nearest .fluid-coding/project.json (a real file), then a .git entry (directory or file); ties go to the manifest.
  3. If nothing meaningful exists, fall back to the canonicalized launch directory itself.
  4. Run the bounded deterministic scan on the chosen root. Repositories are relative checkout paths; . means the root is a checkout. Symlinked subdirectories are never followed out of the root.

source is env, currentDir, gitRoot or manifest; gitRoot and configured record which markers were found. When detection is unavailable, the form keeps manual path entry as a fallback.

Detection seeds the guided state once, when status arrives. Later status fetches and explicit user edits never overwrite what the user has already changed.

What setup does

  1. Reads the local project index (~/.fluid-coding/projects.json) and the plugin registry.
  2. Scans the chosen directory: .git, package.json, tsconfig.json, pom.xml, *.tonel, README.
  3. Proposes a project with one row per repository, language providers and plugin choices with reasons.
  4. Lets the user edit the proposal, answer questions and enable extra permissions explicitly.
  5. On Apply, writes .fluid-coding/project.json, updates the index, activates the project and opens the map.

Safety

  • Nothing is written before Apply. The default trust mode is propose.
  • Paths from a detected project come from the filesystem; path-looking chat text is dropped before proposal so it cannot replace the detected root.
  • Plugin ids are checked against the registry; hallucinated ids are dropped with a warning.
  • network:out and process:spawn permissions require a separate checkbox.
  • If the LLM is unavailable or returns invalid JSON, setup still works offline.

Reconfigure this project lives under Settings as a secondary action (also available as a quiet shell footer link), not in primary navigation. Adding a repository later is the same flow: edit the project definition or rerun setup and merge the proposal.
