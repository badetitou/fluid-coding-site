Brief 04 — ADRs and budget documentation

Goal: record the two boundary decisions and the performance budget before implementation lands.

Read first

docs/plans/session-analysis/00-shared-contract.md, AGENTS.md, docs/decisions/README.md, docs/decisions/ADR-0025-macos-unified-titlebar.md (house style), docs/architecture.md, docs/quality/performance.md.

Work

  1. docs/decisions/ADR-0027-genai-trace-model.md — context: dock sessions store no tool calls, timings or subagents, while provider CLIs can export OTLP. Decision: local loopback OTLP/HTTP JSON receiver, GenAI semconv subset pinned, JSONL under .fluid-coding/traces, pure fluid-core graph builder, content capture opt-in, no native DB reads in v1. Consequences: semconv is Development status so adapters normalise provider variants; correlation by traceparent then conversation/session id + time; traces are gitignored; optional future OTLP export / retroactive import stays an additive adapter.
  2. docs/decisions/ADR-0028-session-analysis-rendering.md — context: user wants zoom, node drag, collapsible chats and subagent groups; hand-rolled SVG would reimplement viewport/hit-testing. Decision: @xyflow/react v13 as a lazy route chunk, custom nodes/edges, Rust-computed layout, React Flow attribution kept. Consequences: ~64–86 KiB gzip in a non-initial chunk, CSS layer ordering, onlyRenderVisibleElements + memoisation, initial bundle must stay <150 KiB.
  3. Update docs/architecture.md: §8 mention the lazy /analysis route and React Flow as the graph surface; §10 describe the OTLP span ingestion behind AgentPort; §11 list .fluid-coding/traces/ as gitignored telemetry. Keep the existing layer rules intact.
  4. Update docs/quality/performance.md with two POC gates: build_session_graph on 10k spans p95 < 20 ms (criterion bench), and analysis canvas at 300 visible nodes keeping 60 fps pan/zoom (Playwright rAF trace). Add the note that the React Flow chunk is lazy and excluded from the 150 KiB initial budget.
  5. Do not edit STATUS.md (final integration is the orchestrator’s job) and do not invent measured results — mark the new gates as “not measured yet” like the existing baseline.

DoD

  • Both ADRs follow the existing Context/Decision/Consequences style and are linked from docs/decisions/README.md if that README lists ADRs.
  • Architecture and budget docs remain internally consistent; no code files edited.
