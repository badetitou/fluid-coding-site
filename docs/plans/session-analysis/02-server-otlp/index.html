Brief 02 — OTLP receiver, local trace store, analysis route

Goal: capture GenAI spans from the agent CLIs into a local store and serve the frozen SessionGraph DTO through one batched route.

Read first

docs/plans/session-analysis/00-shared-contract.md, AGENTS.md, docs/architecture.md, crates/fluid-server/src/chat_sessions.rs, crates/fluid-server/src/app_state.rs, crates/fluid-server/src/routes/mod.rs, crates/fluid-server/src/routes/agents.rs, crates/fluid-server/src/agents/cli.rs, crates/fluid-server/src/settings/model.rs, crates/fluid-server/src/error.rs.

Work

  1. crates/fluid-server/src/session_traces.rs (≤300 lines; split if needed): store rooted at <active project>/.fluid-coding/traces/. Follow ChatSessionStore for id validation, atomic temp-file + rename writes, sorted reads and per-project switching in AppState. Append TraceSpan JSONL per <safeConversationId>.jsonl; cap spans per conversation (e.g. 20k) and bytes per read. Never write foreign JSON into .fluid-coding/sessions/.
  2. OTLP/HTTP JSON receiver at POST /_telemetry/v1/traces, registered in routes/mod.rs. Parse resourceSpans[].scopeSpans[].spans[] with serde: traceId/spanId/parentSpanId hex, startTimeUnixNano/endTimeUnixNano strings → ms, status.code, attributes[] with stringValue|intValue|doubleValue|boolValue, events[]. Map gen_ai.* attributes to the frozen TraceSpan fields (operation.name, provider.name, conversation.id, agent.name, tool.name, tool.call.id, usage.input_tokens, usage.output_tokens, usage.cache_read.input_tokens, error.type); keep the remaining raw attributes sorted by key, capped at 64 keys / 256 chars per value. Reject bodies >2 MiB with a typed error. No external forwarding, no auth besides loopback binding.
  3. Wire the receiver endpoint into crates/fluid-server/src/agents/cli.rs spawn environment only when sessionTracing is enabled: OTEL_EXPORTER_OTLP_ENDPOINT=http://127.0.0.1:<port>, OTEL_EXPORTER_OTLP_TRACES_PROTOCOL=http/json, OTEL_TRACES_EXPORTER=otlp, CLAUDE_CODE_ENABLE_TELEMETRY=1, CLAUDE_CODE_ENHANCED_TELEMETRY_BETA=1, and the opencode experimental.openTelemetry equivalent. Set content flags (OTEL_LOG_USER_PROMPTS, OTEL_LOG_TOOL_DETAILS, OTEL_LOG_TOOL_CONTENT) only when captureGenAiContent is on. Generate a W3C traceparent for the run and pass it as OPENCODE_TRACEPARENT when supported; otherwise correlate by conversation/session id + time. Never mutate the user’s global config files.
  4. Add settings fields sessionTracing (default true) and captureGenAiContent (default false) to the Rust settings model with serde defaults. Do not edit the zod settings schema (owned by track 01): report the exact field names/types so the orchestrator can merge them.
  5. Add GET /api/session-analysis?ids=...&expand=...: resolve each id as a durable chat session id first, then as an external agent session id via the current in-memory sessions; load all traces in one pass, build a SessionTrace, call fluid_core::session_graph::build_session_graph with GraphOptions from query params, return SessionGraph. Validate ids with chat-session rules, max 20 ids, max 200 expand ids; unknown ids produce empty sessions, not errors. Add typed errors.
  6. Tests: OTLP JSON parsing fixture (including missing fields), redaction/caps, id validation, batch route with two ids, and a run-env test asserting content flags stay off by default.

DoD

  • cargo test -p fluid-server passes once track 01 has landed; if it cannot compile before then, report that clearly and do not create stubs in fluid-core.
  • No panic in request paths; loopback only; no file outside your ownership matrix edited.
