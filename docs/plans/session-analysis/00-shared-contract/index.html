Session analysis — shared contract (frozen for v1)

Read AGENTS.md, STATUS.md, docs/architecture.md, docs/quality/performance.md and docs/contracts/wire.md before starting. Rust structs are the source of truth; TypeScript mirrors by hand and a shared fixture is the drift alarm. This contract is frozen: if it looks wrong, report it, do not silently change it in your track.

Decisions locked with the user

  • Source: instrument local agent runs with OpenTelemetry GenAI semantic conventions. The Rust server exposes a loopback-only OTLP/HTTP JSON receiver; the CLI adapters inject the endpoint into the spawned provider process. No read of opencode/Claude native databases in v1.
  • Storage: .fluid-coding/traces/<safeConversationId>.jsonl, gitignored, append-only, atomic writes.
  • Placement: a dedicated lazy route /analysis?ids=<id1,id2> under Shell, opened from Agents (single session and multi-select). No new primary nav item.
  • Rendering: @xyflow/react v13 (React Flow 13), lazy-loaded, v13 CSS in the lazy chunk.
  • Sub-agents: nested spans become expandable parent groups in the same canvas, with breadcrumbs.
  • Tool calls: consecutive execute_tool spans between two turns become one arrow per segment; stroke width + colour intensity encode callCount; click expands into bounded pages of nodes.
  • Content (prompts, tool args/results) is opt-in, default off. Metadata only by default.
  • GenAI semconv is Development status: pin this subset, keep raw attributes capped and sorted.

Frozen TypeScript mirror

packages/contracts/src/session-graph.ts exports zod schemas with the same camelCase fields: tokenUsageSchema, spanAttributeSchema, traceSpanSchema, traceSessionSchema, sessionTraceSchema, graphOptionsSchema, graphNodeSchema, graphEdgeSchema, graphStatsSchema, sessionGraphSchema, plus inferred type aliases with the PascalCase names above. Re-export all of them from packages/contracts/src/index.ts.

Fixture: fixtures/contracts/session-graph.json — one SessionTrace with a parent session, one subagent, three consecutive tool spans and one error span. Parsed by Rust tests and packages/contracts/src/fixtures.test.ts.

Frozen HTTP surfaces

  • GET /api/session-analysis?ids=<id1,id2>&expand=<spanId1,spanId2> → SessionGraph. One request for the whole selection (no N+1). ids required, max 20, validated with the same id rules as chat sessions. Unknown ids produce sessions with no spans, not a 500.
  • POST /_telemetry/v1/traces → 200/204. OTLP/HTTP JSON ExportTraceServiceRequest, max 2 MiB, loopback only, no external forwarding. Cap raw attributes at 64 keys and values at 256 chars.
  • Web client: fetchSessionAnalysis(ids: string[], expand: string[]): Promise<SessionGraph> in apps/web/src/api/coding.ts, validated with sessionGraphSchema.

Settings additions

sessionTracing: boolean default true; captureGenAiContent: boolean default false. Mirrored in the settings zod contract, Rust settings model and General settings UI.

Integration rules

  • Cross-track imports may not compile until the owning track lands. Write code against the frozen contract; report blocked checks instead of creating stubs or touching another track’s files.
  • Keep Rust modules ≤300 lines, React components ≤150 lines and ≤7 props, pure logic in model.ts with colocated tests. No any, no panic in request paths.
  • Run the narrowest checks for your track: cargo test -p fluid-core, cargo check -p fluid-core --target wasm32-unknown-unknown, cargo test -p fluid-server, pnpm --filter @fluid-coding/contracts test, pnpm --filter @fluid-coding/web typecheck. Full workspace gates are for final integration only.
