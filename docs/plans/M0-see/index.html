M0/POC — See, task, edit, review

Status: proposed, 2026-11-25. Scope superseded by ADR-0012: the first POC is the installed, dogfoodable loop, not a read-only viewer.

Goal

Install fluid-coding locally, open a repository, pick a task, understand its structure, hand it to a real agent, review a patch with evidence, apply it with a checkpoint, and continue in the same shell. Every fact comes from Rust; the web shell renders and filters. The same facts are available to external agents through MCP read tools. LLM narrative is present as a plugin but is never evidence.

Demo script

  1. bash scripts/install-local.sh; launch ~/Applications/fluid-coding.app. The app serves the embedded web on loopback and opens the browser.
  2. Tasks shows local Markdown issues plus normalized GitHub/GitLab snapshots; select one and copy its brief to the agent dock.
  3. The map shows layer × domain cells; select business:codegraph; the URL carries the selection.
  4. Miller columns show symbols, then relations, with tag badges. Monaco opens the selected file with LSP-style navigation; “Open in VS Code” remains available.
  5. Ask opencode or Claude Code for the task. Its adapter returns messages and a patch proposal through AgentPort; the chat shows the Change Brief separately from optional LLM narrative.
  6. Review hunks, apply with explicit edit trust, and restore a checkpoint to prove undo.
  7. Changes shows changed and impacted cells, the diff and the deterministic brief.
  8. Tags: accept a proposal or propose a tag; a file is written under .fluid/tags/.
  9. From an external agent: get_matrix, get_impact, get_diff, list_tags, list_tasks, get_task, task_brief return the same contract-valid JSON.

Acceptance criteria

  • Installed macOS app serves embedded web assets; binds only 127.0.0.1; --no-open, --port and --print-url work.
  • Rust server serves /api/health, /api/matrix, /api/impact, /api/graph, /api/entity/{key}, /api/relations/{key}, /api/tags, and the Tasks/Edit/Checkpoint/Agent/ Narrative routes; the demo fixture loads.
  • Cached matrix p95 < 20 ms; impact p95 < 100 ms at 100k LOC; cold start < 150 ms.
  • A working tree is head: null; impact distances match the reverse-edge BFS.
  • Initial JS < 150 KB gzip (pnpm check:bundle); Monaco is lazy and excluded from the initial bundle; FCP < 300 ms local.
  • The map draws 5,000 cells at 60 fps pan/zoom; only visible cells draw; lists over 100 rows virtualize.
  • Selection lives in the URL; one request per selection, no N+1.
  • Change Brief shows files, symbols, cells, checks and risk; LLM narrative is visually separated.
  • A chat turn can propose a patch; apply creates a checkpoint with exact prior contents; restore returns the files to that state. propose is default and rejects direct writes.
  • Fake, opencode and Claude Code adapters implement the same AgentPort; unknown adapters 404.
  • TypeScript/JavaScript, Java and Pharo Tonel providers implement LanguagePlugin; live Pharo is a later adapter with the same trait.
  • Tags: accept/propose writes .fluid/tags/<id>.json; orphan is computed at read time, never stored.
  • MCP read tools return contract-valid JSON; propose_tag requires trust mode and is audited.
  • Dogfood note in the PR: what was tried in the installed fluid-coding and what the map missed.

Tasks 2–4, 9–10 and 12 are Rust/plugin tracks; 5–7 and 11 are web tracks. They meet at the shared fixtures and zod contracts, not ad-hoc JSON. Every slice must stay independently reviewable.

Dependencies

  • Rust core/server: fluid-core types, matrix, impact, tags, brief, tasks, plugin ports; axum endpoints; generation.
  • Web shell: routes, canvas map, Miller columns, Changes/Tasks pages, Monaco, agent dock; no graph logic in React.
  • MCP read tools: get_matrix, cell_symbols, get_entity, get_relations, get_impact, get_diff, list_tags, list_tasks, get_task, task_brief; writes behind trust mode.
  • Contracts: hand-mirrored zod schemas plus shared fixtures are the interim guard until fluid-contracts-gen exists.

Out of scope for this POC

  • Hosted multi-user collaboration, CRDT, auth.
  • SQLite as source of truth; .fluid/ files and .claude/issues/ remain canonical.
  • Live GitHub/GitLab write-back: tasks are normalized snapshots with capability manifests for now.
  • Live Pharo via PLexus/MCP: static Tonel provider first, same trait later.
  • Arbitrary plugin sandboxing beyond typed manifests and explicit trust modes.

Risks

Risk Impact Mitigation
SymbolLinker cannot join Structure ids and Model SCIP keys reliably wrong cells, wrong impact spike on a real TS repo; SCIP first, file + name + range fallback; expose confidence; do not block POC on perfect links
Map at 5,000 cells dropped frames, unusable home canvas, draw only visible cells, no React node per cell; aggregate at low zoom; Playwright rAF trace early
Contract drift until codegen web compiles against stale shapes shared fixtures in both test suites; one-PR rule; add fluid-contracts-gen later
Agent CLI output varies adapters break silently parse into zod/serde contracts, fake adapter in tests, typed PluginError, no shell strings
LLM narrative looks authoritative bad trust decisions facts first, narrative separated and labelled, never used as evidence
Patch application corrupts files loss of work pure hunk validation, checkpoint before write, traversal rejection, restore test
Two toolchains CI blind spots CI runs Rust and web jobs; the wasm check catches I/O creep in core

Dogfood

Before closing the POC, run the installed app on fluid-coding itself: pick a real local task, open the matrix, ask an agent for a patch, review its brief, apply it, restore a checkpoint, and call the MCP read tools from an external agent. Record in the PR: the matrix and impact of the change, initial JS gzip, what the map made obvious, and what it missed. The dogfood note is part of done, not a demo afterthought.
