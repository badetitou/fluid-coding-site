Create a project: one field

Status: chosen direction (option A), draft for implementation. Issue #18. Replaces the two-mode page in SetupPage.tsx as the default path. Contract and detection rules stay those of ADR-0015.

Purpose

A first-time user gives one folder and gets a working project. Every other decision is optional and hidden until asked for. The flow still produces the same validated SetupProposal, and nothing is written before Create.

Flow

  1. Folder field (Folder of your project). Pre-filled from the launch directory when one was detected. Drag-and-drop or paste. Detection runs on blur or Enter, offline, through the existing deterministic scan.
  2. Confirmation card appears when the folder is found: name, repository count, languages, a Found tag. Nothing to fill in.
  3. Details (collapsed <details>): name, suggested plugins, permissions, open questions. Opening it does not change the default; the proposal stays valid without touching it.
  4. Create project is the only primary action. It applies the proposal, writes .fluid-coding/project.json, activates the project, then goes to the map (same as today’s apply).

Common case: one decision (the folder), one click.

Error state

  • Folder not found: the field gets aria-invalid, one role="alert" message (“We can’t find that folder.”) with two actions: Browse folders and a suggested path when one is close. Create stays disabled.
  • Detection fails for another reason: the same alert shape, message from the server, no silent fallback.

Decisions taken here (to confirm in review)

  • The Guided / Chat tabs leave the first screen. Chat stays reachable from Details as a fallback for someone who wants to describe the project. Guided form fields are the Details fields.
  • The review panel is no longer a separate step: its content lives in Details.
  • Permission consent appears only when the proposal needs a permission the user has not allowed. Otherwise it is not shown.

Accessibility and layout

  • Single column, max width 560 px, works at 375 px without horizontal scroll.
  • Input labelled; errors announced; focus moves to the alert when it appears.
  • Keyboard: Enter in the field runs detection; Tab order is field → Details → Create.
  • Respects prefers-reduced-motion; light and dark from the existing tokens in styles.css.

Out of scope

  • Hosted registries, automatic indexing at setup time, changes to the Rust proposal logic.

Implementation slices (proposed, one PR each)

  1. Pure model for the one-field state (detected / not found / detecting) with tests next to lib/setupCore.ts.
  2. Components: folder field, confirmation card, Details disclosure, each under 150 lines.
  3. Wire SetupPage to the new default; keep guided and chat inside Details. Remove the tabs from the first screen.
  4. Dogfood note in the PR: run cargo run -p fluid-server and pnpm dev, create fluid-coding itself from its folder.
