Session graph contract

Status: accepted with the session-analysis v1 contract. Rust owns the wire shape in fluid-core/src/session_graph; TypeScript mirrors it in packages/contracts/src/session-graph.ts; fixtures/contracts/session-graph.json is parsed on both sides as the drift alarm.

All fields are camelCase. Option<T> is always serialized as null when absent. Vec and maps are ordered; there are no hash-ordered fields.

Example

The fixture contains a parent session, one nested subagent session, three consecutive tool spans and one error span:

The remaining spans follow the same shape; see the fixture file for the complete trace. Responses from GET /api/session-analysis are SessionGraph values: sessions, nodes, edges, stats.

Node kinds

kind Source
session A TraceSession lane, or a top-level invoke_agent span
turn chat (also inference, completion, text_completion)
toolBatch One or more consecutive execute_tool spans
tool An individual tool span inside an expanded batch
subagent An invoke_agent span with a span parent
exception An exception span
message Any other operation, including provider-specific strings preserved verbatim

Invariants

  • One lane per input TraceSession, in input order. Depth follows the topological order of parentSpanId, then startMs/spanId for stable ties. Reversing span input order does not change the graph when timestamps and ids are equal.
  • Consecutive execute_tool spans in a lane collapse into one GraphEdge between the surrounding non-tool nodes. callCount, totalDurationMs, avgDurationMs (integer division) and errorCount summarize the batch; toolNames holds at most 8 distinct sorted names.
  • intensity = min(callCount / max(maxCallsPerBatch, 1), 1) and is clamped to 0..1.
  • GraphOptions.expanded lists span ids from a batch. An expanded batch emits individual tool nodes as children, capped by maxCallsPerBatch; the aggregate edge stays in place.
  • maxNodes caps every emitted node, including lane roots. Every node that cannot be emitted is counted in stats.droppedNodes; tool calls beyond an expansion cap are counted there too. A collapsed batch is one node, not one node per call.
  • Missing parent ids attach to the lane root. Cycles are broken deterministically (one cycle member becomes a root); no path recurses forever and no parent id dangles.
  • contentRef is null unless content capture was explicitly enabled upstream. Metadata is always present; prompts and tool payloads are never inferred by the core.
  • No I/O, clock, randomness or async in fluid-core; the same input always serializes identically.

Defaults

GraphOptions defaults to maxNodes: 300, maxCallsPerBatch: 8, expanded: [].
